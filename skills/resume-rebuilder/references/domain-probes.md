# 领域自适应追问清单（domain-probes）

阶段 2 深挖时，根据用户提到的技术/系统，查阅对应区块，提出**具体到技术细节**的追问，把能写进简历的硬货挖出来。问题要能"引导回忆 + 显出专业度 + 逼出量化"。

通用提醒：每个方向都叠加「规模/架构取舍/踩坑优化/角色/量化/业务价值」六维度（见 SKILL.md 通用追问维度）。

---

## 前端（含框架 React/Vue、性能、可视化）

- 用了哪个框架/构建工具？为什么选它，有没有对比过别的？
- 性能优化做了哪些？首屏时间、包体积、Lighthouse 分数变化？路由懒加载、代码分割、缓存策略？
- 有没有处理过大列表/大数据渲染卡顿？虚拟滚动、Web Worker？
- 状态管理方案？为什么这么选？
- 和后端协作的接口设计？有没有对接过流式/WebSocket/SSE？
- 组件库是自研还是二次封装？解决了什么复用问题？
- 有没有做工程化（CI/CD、单测覆盖率、监控）？

## AI / LLM / Agent 开发

- Agent 的整体架构？用了什么框架（LangChain / 自研 / 某平台）？多智能体还是单智能体？
- 怎么编排任务/工具调用？有没有做 planning、反思、记忆机制？
- 提示词工程做了什么？怎么迭代优化的？
- 有没有做评测/评估体系？准确率、成功率怎么量的？
- 和 RAG 结合的细节见下方 RAG 区块。
- 延迟/成本优化？模型路由、缓存、并发？
- 线上稳定性：超时、重试、降级、观测怎么做？

## RAG / 知识库

- 支持哪些文件类型？解析用了什么（pdfplumber、 unstructured、OCR）？
- 怎么分块（chunk）的？固定长度还是语义分块？块大小怎么定的？
- 向量化用哪个模型/服务？有没有做混合检索（BM25 + 向量）？
- 怎么提升检索精准度？重排（rerank）模型？query 改写/扩展？
- 有没有做缓存、增量更新、权限隔离？
- 检索不准时你第一步查的是哪层（召回/排序/生成）？
- 效果指标：命中率、回答准确率怎么评估的？

## 3D / 地图 / Cesium / 数字孪生

- 大量实体同屏渲染卡顿怎么解决？LOD、实例化（InstancedMesh）、可见性剔除、贴地优化？
- 运动轨迹怎么设计的？插值、时间轴、数据驱动？
- 数据接入：实时数据怎么更新？WebSocket/SSE 还是轮询？频率多少？
- 地形/影像瓦片怎么加载的？离线包、缓存策略？
- 和后端的数据接口规模？每秒多少点位？
- 有没有做拾取/交互/标绘功能？

## 后端 / 服务端 / 数据

- 技术栈与架构？单体还是微服务？为什么这样分？
- 高并发怎么处理的？缓存（Redis）、消息队列、分库分表？
- 数据库选型与优化？慢查询怎么定位、索引怎么设计？
- 接口性能？QPS、P99 延迟、怎么压测的？
- 有没有做容灾/限流/降级？
- 数据 pipeline / ETL 怎么设计的？量级多大？

## 通用"引导回忆"话术（用户想不起细节时）

- "当时你接手这事的时候，它最让你头疼的点是什么？"
- "你是怎么发现瓶颈/问题的？是先 profile 还是凭经验猜？"
- "如果现在有人来接你的班，你最怕他踩哪个坑？"
- "这事你是一个人扛，还是拉了谁一起？你具体负责哪块？"
- "上线之后，第一个正向反馈是什么？"

## 双向 coaching 话术（用户实现得过得去时）

- "你现在的做法能跑通，不过业界常用的更优解是把 X 换成 Y，好处是…如果当时用了，简历能写'将…从 A 降到 B'。"
- "这块其实可以补一层 Z（如监控/评测/缓存），不仅能提升稳定性，简历里也能多一条'建设了 XX 能力'。"
- 给出更优方案的**同时**，务必把这层也落成一条可写进简历的条目供用户参考。
