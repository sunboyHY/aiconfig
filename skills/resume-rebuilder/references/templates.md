# 模板（templates）

## 会话内备忘录模板

在阶段 0 建立，路径按运行环境动态选择（见 SKILL.md 原则：优先用会话临时目录，否则系统临时目录，不要写死 `/tmp`）。每锁定一块就追加/更新。后续只信此文件。

```markdown
# 简历草稿 — <用户标识> — <日期>

## 基本信息
- 当前背景：<如 前端 3 年>
- 目标岗位：<岗位名>
- JD 核心要求：<3-5 条关键词/能力>

## 规划
- 项目清单：A / B / C
- 权重分配：<如 目标方向 70% / 旧背景 30%>

## 锁定内容

### 项目 A — <一句话>
状态：✅已锁定
口语原话：<用户原话>
简历写法：
- <动词+内容+量化>
- <动词+内容+量化>
JD 匹配：<对应 JD 哪条 ✅>
【必填字段】
- 角色边界：<独立/带人/协作，个人贡献边界>
- 业务价值：<对业务/用户/团队带来的改变>
- coaching 建议：<给过的更优方案或升级后的条目；没做就写"无">
- 回忆触发点：<哪个提问帮用户想起关键细节；没做就写"无">

### 项目 B — <一句话>
状态：🔄进行中
...

## JD 差距分析
- 匹配 ✅：<逐条对应 JD 要求>
- 缺口 ⚠️：<逐条，每条给三层：现有经历怎么凑 / 如何弱化呈现 / 是否值得学 + 学习路径或"不建议硬补">
```

## 缺口清单"是否值得学"格式示例

> JD 要求：精通 Python、Milvus/FAISS、Function Calling
>
> - **Python（硬门槛）**：现有经历已用 Python 起模型推理服务，可包装为"封装 LLM/ASR 推理服务"来凑，不单独写"精通 Python"→ 不建议为投递现补系统级 Python，面试可强调工程化能力。
> - **Milvus/FAISS（加分项）**：目前用 PG/pgvector + 内存向量库，是同类能力 → 建议补齐：值得学，成本低（官方 quickstart 半天上手），可做一个小 Demo（如替换现有向量库为 FAISS 跑通检索）后再写进简历。
> - **Function Calling（硬门槛）**：现有语音指令用"规则映射+LLM 兜底"，不是标准 Function Calling → 如实写"类工具注册机制"，并推荐：值得学，LangChain/LangGraph 官方文档有 Function Calling 教程，可把现有语音路由改造成标准工具调用作为练习项目。

  - <动词+内容+量化>

## 项目经历
### <项目名> — <角色> — <时间>
- <动词+内容+量化>

## "口语原话 → 简历语言"对照示例

> 口语原话：我搞了个小助手，能查数据库，然后回答问题，还挺好用的。
>
> 简历语言：主导搭建基于 LLM 的问答助手，接入内部数据库实现自然语言查询，将非技术同学的数据获取耗时从约 30 分钟缩短到分钟级。
